# Вторая задача: график и замечания тимлида

Это согласованный по сообщению пользователя объём следующего этапа.
В поставке Model Adapter изменения frontend ещё не выполняются.

## Текущее состояние

Есть React/Recharts-график predicted/lower/upper, переключение горизонта,
выбор даты, таблица и карта Leaflet/OSM. При успехе запросов график получает
данные API, но `api.ts` при ошибке незаметно подставляет локальный mock.
Он игнорирует выбранные даты, поэтому видимый график сам по себе не доказывает
успешное подключение backend. Шкала времени графика использует локальный
часовой пояс браузера; API и таблица используют Москву.

## Объём следующей реализации

| Требование | Запланированное изменение | Как принимать |
| --- | --- | --- |
| График из API | Явные loading/error/empty; не скрывать сбой API локальными данными | Отключение backend даёт понятную ошибку; значения совпадают с ответом API |
| Горизонты | День/месяц/год и корректные календарные интервалы | 24 часа, 28–31 день, 12 месяцев; отдельный февраль високосного года |
| Tooltip | Время интервала в МСК, прогноз, единицы и доступные границы | Подписи совпадают с API независимо от часового пояса браузера |
| Понятная ось Y | Название величины и единица из метаданных; пояснение синтетики | Нет необоснованных «пассажиров» или «% заполнения» |
| Границы/actual | Nullable-границы; actual не выдумывать | `null` не рисуется как ноль; actual появляется только при согласованном источнике |
| Яндекс Карты | Заменить Leaflet/OSM на Яндекс API | Карта, точки и выбор маршрута работают; ошибка загрузки объясняется |
| Таблица | Предлагаемый вариант: открывать отдельную панель по кнопке «Данные» | Основной экран показывает график, таблица доступна по требованию |
| Сортировка | По времени/прогнозу/границам, вверх/вниз; ясный порядок для null | Видимый порядок соответствует заголовку, равные значения стабильны |
| Экспорт | CSV видимых данных с датами, единицами и границами | Открывается в Excel; соответствует выбранному периоду и сортировке |
| Календарь | Popover с навигацией месяц/год и понятным выделением выбранной даты | Работает мышью и клавиатурой; неделя с понедельника; выбор отражён в запросе |

Фотографии пользователя показывают текущие график, таблицу, системный календарь
и Trello как ориентир календаря. Не требуется переносить в продукт напоминания
или повторяющиеся сроки Trello. XLSX можно добавить отдельно, если CSV недостаточно;
в текущем замечании тимлида разрешены оба варианта.

## Смысл показателя

До определения target текущие `demo_index/demo_mean` обозначают демонстрационную
величину. В mock базовый уровень зависит от ключа ряда, добавляются утренний и
вечерний пики, выходным применяется коэффициент 0.75; для длинных интервалов
усредняются почасовые значения. Границы ±15% иллюстративны и не являются оценкой
статистической уверенности. Подробности расчёта находятся в `predictors/mock.py`.

Постоянный продуктовый «индекс загруженности» сейчас вводить не требуется.
Когда команда согласует реальную цель, отображение должно следовать её единице.
Top-N по predicted_load означает максимальные значения, а перегрузка требует
отдельного порога/вместимости. Заголовки UI должны учитывать это различие.

## Зависимости, которые учитывать перед работой

- Для Яндекс API потребуется ключ проекта и настройка допустимых доменов;
  проверить выбранную версию API и условия использования на этапе реализации.
  Ключ и настройки должны передаваться окружением, инструкция — в README.
- Полностью офлайн-карта и подключение онлайн-карт Яндекса — разные режимы;
  при недоступном картографическом сервисе остальные элементы должны работать.
- `getMapForecast` и `getTopOverload` уже существуют, но текущие компоненты ими
  не пользуются. Карта рисует постоянный цвет маршрута, а Top-5 сортирует время
  одного ряда. При подключении географического среза согласовать timestamp
  с выбранным интервалом и учитывать направление/повторные посещения остановки.
- У snapshot-запроса с origin за пределами горизонта найден ответ 500;
  при работе с запросами карты следует исправить валидацию на предсказуемую 422.
- Добавление поля actual в публичный контракт требует согласования; отсутствие
  фактических наблюдений не мешает выполнить обязательный DoD этой карточки.

Статусы Trello и приоритет дополнительных UI-пунктов определяет команда.
Этот документ фиксирует анализ, а не объявляет вторую задачу выполненной.
