# Предрелизная проверка TramFlow UI v3

Дата проверки: 27 сентября 2026 года.

## Результат

Проект запущен локально в режиме `CATALOG_BACKEND=memory`: FastAPI и Vite работали отдельными процессами, запросы frontend проходили через штатный прокси `/api`. Ошибок frontend и backend в логах итогового прогона не обнаружено.

| Backend pytest | 92 passed, 2 skipped |
| Frontend unit-тесты | 10 passed |
| TypeScript | `tsc --noEmit` успешно |
| Production-сборка | Vite build успешно |
| Backend readiness | HTTP 200, `catalog_backend: memory` |
| Каталог через Vite `/api` | 36 маршрутов; интерфейс фильтрует 9 поддерживаемых |

| Сетевой срез | 2132 точки |

## Браузерный smoke-тест

Проверены desktop 1440×1000 и mobile 390×844, светлая и тёмная темы:

- открытие «Мониторинга» и загрузка карты, показателей, графика и сводки;
- ширина правой панели и отсутствие горизонтального переполнения;
- расположение кнопки параметров у левого края заголовка;
- календарь открывается непосредственно под полем даты без пустой области;
- раскрытый барабан целиком помещается в viewport и не обрезается панелью;
- один жест колеса мыши перемещает барабан ровно на один пункт;
- «Все остановки» открывается как барабан с карточкой выбранной остановки;
- Split View мониторинга создаётся перетаскиванием правого края;
- оба окна мониторинга содержат показатели, прогноз и сводку маршрута;
- открытие «Сети», сетевой барабан маршрутов и мобильная компоновка;
- Split View сети создаётся перетаскиванием края и показывает полную правую панель в обоих окнах;
- отсутствуют необработанные ошибки JavaScript, HTTP 404/500 и упавшие запросы итогового прогона.

Во время проверки исправлены три найденные проблемы: заголовок карты сети и зоны Split View привязаны к контейнеру карты, остановки очищаются синхронно при смене маршрута, а узкие split-окна и мобильные карточки получили более читаемую компоновку.

## Ограничения среды проверки

Docker в среде проверки отсутствовал, поэтому Compose-сценарий с PostgreSQL не запускался. Backend проверен полным набором тестов и локальным запуском с каталогом из `mock_data`. Ключ Яндекс Карт не задавался, поэтому браузерный прогон использовал штатную схематическую карту OpenStreetMap. Перед показом с Яндекс Картами следует задать локальный `VITE_YANDEX_MAPS_API_KEY`.

## Контрольный запуск на Windows перед демонстрацией

```powershell
Copy-Item .env.example .env
docker compose up --build -d --wait
docker compose ps
```

После запуска открыть `http://localhost:5173` и вручную проверить отображение логотипа Яндекс Карт с реальным локальным API-ключом. Секретный ключ не добавлять в архив или Git.
