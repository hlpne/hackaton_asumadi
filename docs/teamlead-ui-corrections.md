# Правки интерфейса по ревью тимлида

Дата реализации: 26 сентября 2026.

Этот документ сопоставляет замечания ревью с реализацией и повторяемой проверкой.

| № | Что реализовано | Как проверить |
|---|---|---|
| 1 | Маршруты и остановки выбираются через scroll-snap барабан с центральной активной строкой, клавиатурой и mouse wheel. Календарь не заменён барабаном. | Открыть «Мониторинг», раскрыть маршрут, «От» и «До»; прокрутить и нажать стрелки клавиатуры. |
| 2 | Кнопка обновления находится в фиксированной нижней зоне панели и не зависит от высоты horizon-контрола. | Последовательно выбрать день, месяц и год: кнопка не должна смещаться. |
| 3 | Для месяца дата `01` задаёт календарный месяц; другая дата — полуинтервал ровно 30 дней от выбранной даты. | Сравнить `01.09.2026` и `26.09.2026`; выполнить `npm test`. |
| 4 | В годовом режиме календарь заменяется компактным выбором только года. | Переключить horizon на «Год», изменить год стрелками. |
| 5 | Выбрана dark-first схема «чёрно-синий + красный»: синий — действия/фокус, красный — транспортный акцент и трамвай, оранжевый — внимание. | Сравнить dark/light, карту, focus и состояния загрузки. |
| 6–7 | Выбор периода перенесён в расширенную правую панель. Внешняя панель использует glass-эффект; длинные аналитические поверхности остаются непрозрачными. | Открыть «Мониторинг» на desktop и проверить панель справа. |
| 8 | График расположен перед сводкой маршрута. | Получить прогноз и прокрутить аналитическую панель. |
| 9 | Геометрия маршрутов кешируется, обработчики Yandex Map стабилизированы, controls и подписи разнесены по безопасным зонам. | Несколько раз переключить маршрут/направление и проверить отсутствие дублирующихся слоёв и наложений. |
| 10 | Индикатор высокой загрузки расположен снизу по центру карты и сохраняет оранжевую семантику. | Выбрать маршрут с точками повышенной загрузки. |
| 11–12 | Split View поддерживает 2–4 окна, перетаскиваемые вертикальный/горизонтальный разделители и индивидуальные route/direction/date/horizon для каждого окна. | Нажать «Разделить карту», выбрать 4 окна, изменить параметры и размеры каждого окна. |
| 13 | UI-фильтр оставляет девять согласованных маршрутов. Остальные ID сохранены комментарием в `frontend/src/supportedRoutes.ts`; backend-данные не удалены. | Выполнить `npm test`; пересчитать варианты барабана и маршруты «Сети». |
| 14 | «Сеть» перестроена вокруг большой карты; метрики и списки находятся в правой панели. | Открыть «Сеть» и проверить, что карта — основной canvas. |
| 15 | Для близких/общих участков строятся точки выбора с меню доступных маршрутов. | На карте «Сети» нажать маркер пересечения и выбрать маршрут в меню. |
| 16 | В компактную навигацию возвращена отдельная страница «Главное». | Нажать «Главное» и перезагрузить URL с `#home`. |

## Автоматическая проверка

```powershell
cd frontend
npm ci
npm test
npm run build

cd ..\backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests -q
```

Ожидаемый результат текущей версии: `7` frontend-тестов и `92 passed, 2 skipped`
backend-теста без необязательного CatBoost. С установленными зависимостями примера
два artifact-теста также должны выполняться, а не пропускаться.

## Локальная визуальная приёмка

Для финального screenshot review нужен реальный браузер и ключ Яндекс Карт. Проверить:

- `1440 × 900` и `390 × 844`, dark и light;
- обычный мониторинг и Split View на четыре окна;
- отсутствие перекрытия встроенных элементов Яндекс Карт;
- меню пересечения на странице «Сеть»;
- mouse, touch и keyboard-взаимодействие с барабанами и разделителями;
- reload с сохранением темы и URL-параметров каждого split-окна;
- fallback без `VITE_YANDEX_MAPS_API_KEY`.

Результат screenshot review следует приложить к Pull Request.
