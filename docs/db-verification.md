# Проверка доработки PostgreSQL

Дата: **13 сентября 2026 года**. Карточка: `[P0][DB]`.

## Что изменено

- Добавлен `docs/db.md`: все поля четырёх таблиц, связи, ограничения, границы
  целостности, запуск на Windows/Linux/macOS, применение SQL, приёмка и диагностика.
- Добавлены команды `manage.sh migrate|seed|status|check|shell`. Они используют
  настройки контейнера и останавливаются при ошибке SQL.
- Добавлены 31 SQL-проверка и изолированная Docker-приёмка с повторным применением
  схемы/seed. Тестовые строки откатываются, рабочий volume не используется.
- Рабочий Compose монтирует каталог `db/` с командами и тестами. Внешний порт
  учитывает `DB_PORT`; внутренняя связь backend → `db:5432` сохранена.
- Healthcheck БД проверяет TCP `127.0.0.1`, как и соединение приложения, вместо
  проверки только локального Unix-сокета.
- SQL-схема, HTTP-контракт и код приложения сохранены. Создавать новую миграцию
  без изменения схемы не потребовалось.

## Выполнено в среде подготовки

Docker daemon и нативный сервер PostgreSQL здесь недоступны. Для реального
исполнения SQL использован **PostgreSQL 16.3 в WASM-сборке PGlite 0.2.0**,
Node.js 24.19.0. Это выполнение SQL движком PostgreSQL, но **не проверка контейнера**,
TCP-аутентификации, psql или Docker volume. PGlite не является зависимостью проекта
и не требуется участникам команды для запуска.

| Проверка | Результат |
|---|---|
| Выполнение исходного `001_initial.sql` на пустой БД | Успешно; четыре таблицы созданы |
| Выполнение исходного seed | 3 маршрута, 24 остановки, 48 связей, 0 прогнозов |
| Два повторных применения схемы и seed | Успешно; полный снимок значений не изменился |
| `db/tests/check.sql` без изменения SQL для PGlite | Все 31 проверки прошли |
| Состояние БД после отката тестов | Полный снимок строк совпадает с исходным |
| Закрытие и повторное открытие файловой БД PGlite | Данные сохранены; это не тест Docker volume |
| Контроль чувствительности: удалён FK `forecasts.stop_id` в одноразовой БД | Тест корректно завершился ошибкой `forecast rejects a missing stop` |
| Дополнительная проверка на PostgreSQL 18.3 / PGlite 0.5.8 | Тот же сценарий прошёл; целевая версия проекта остаётся 16 |
| Shell-скрипты | `sh -n` прошёл; окончания строк LF |
| Оба Compose-файла | YAML разобран; пути локальных mount существуют |
| Разбор YAML | Статическая проверка, не запуск Compose и не проверка Docker-сети |

Проверки охватывают запись/чтение прогнозов, JOIN, внешние ключи, удаление
используемых справочников, повторные посещения остановок, координаты, время,
day/month/year, интервалы, нечисловые/бесконечные значения и уникальность с NULL.

Принадлежность существующей остановки маршруту/направлению не является ограничением
текущей БД; граница подробно описана в `docs/db.md`. Этот пункт не выдаётся за
пройденную SQL-проверку. Backend/frontend не менялись; прежние результаты их проверки
относятся к исходному каркасу и находятся в [verification.md](verification.md).

## Подтверждённый запуск Docker на компьютере участника

Источник: вывод PowerShell, предоставленный Игорем в чате 13 сентября 2026 года.
Команды выполнены из распакованного проекта `mt-transport-db-task1/mt-transport-db`.

| Проверка | Фактический результат |
|---|---|
| `docker compose up -d --wait db` | Контейнер `mt-transport-db-db-1` Healthy |
| Версия сервера | PostgreSQL 16.15, x86_64-pc-linux-musl, Alpine, 64-bit |
| База данных | `transport` |
| Таблицы | `routes`, `stops`, `route_stops`, `forecasts` |
| Строки до перезапуска | 3 / 24 / 48 / 0 соответственно |
| `docker compose restart db`, затем `up -d --wait db` | Контейнер снова Healthy |
| Строки после перезапуска | 3 / 24 / 48 / 0, совпадают с исходными |
| `manage.sh check` внутри контейнера | Все 31 сообщения PASS; завершение `DO`, `ROLLBACK`, `DB_CHECK_OK` |
| PowerShell и shell-команды внутри образа | Приведённые команды успешно выполнены участником |

**Четыре требования DoD карточки DB подтверждены:** PostgreSQL запускается,
SQL создаёт четыре таблицы, базовые связи работают, схема описана в `docs/db.md`.
Технически карточка готова к закрытию и ревью руководителем. Этот отчёт не меняет
статус Trello автоматически.

`forecasts = 0` ожидаемо: проверка откатывает свои записи, а постоянный demo seed
прогнозов относится к следующей задаче. Работа frontend/backend целиком в Docker
из данного вывода не следует и не является отдельным требованием этой DB-карточки.

В предоставленном выводе нет SHA локального Git-коммита, версий Docker/Compose,
отдельного значения `$LASTEXITCODE` и прогона `db/compose.test.yml` с маркером
`DB_ACCEPTANCE_OK`. Их не считаем полученными. Маркер `DB_CHECK_OK` выводится
скриптом только после успешного завершения psql; фактические требования текущей
карточки подтверждены показанным запуском и проверками рабочей БД.

Изолированный прогон на новой БД остаётся дополнительным воспроизводимым сценарием
для команды и будущих изменений, а не новым обязательным требованием Trello:

```bash
docker compose -f db/compose.test.yml up --force-recreate --abort-on-container-exit --exit-code-from check
```

Для него ожидаются `SEED_REPEAT_OK`, `DB_CHECK_OK`, `DB_ACCEPTANCE_OK` и код `0`.
Порядок отправки изменений руководителю: [github-db-review.md](github-db-review.md).

Описание используемого встроенного движка: [PGlite](https://pglite.dev/docs/about).
