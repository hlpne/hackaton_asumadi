# Прогноз загрузки трамвайных маршрутов — финальное решение (скор 0.90461)

Прогноз посадок (успешных валидаций) **маршрут × дата × час** на 01.11–31.12.2025: 10 маршрутов, 14 640 строк.

Схема решения:

1. **ML-контур.** Потоковая LightGBM-модель, которая идёт день за днём и отдаёт объём и профиль часов.
   - Модели сохранены как артефакты: LightGBM `.txt`, ONNX и `manifest.json`.
   - Инференс работает на трёх движках: LightGBM, ONNX Runtime в Python и **ONNX Runtime в JVM (Java)**.
2. **Гибрид с математической моделью.** Сумма за день = 0,5 × ML + 0,5 × медиана 4 последних недель; профиль часов берётся из ML.
3. **Сезонная надбавка к декабрю** по открытым данным data.mos.ru за прошлые годы. Итог шагов 1–3 — «ML-гибрид».
4. **Математическая модель v1** — ранняя версия математической модели (без погоды, со своим правилом для маршрута 5) с уточнениями из основной версии, включая **хвост 1 ноября** (используется **с разрешения организаторов**). Скор 0.90339.
5. **Финальный ансамбль**: 0,4 × ML-гибрид + 0,6 × математическая модель v1. Скор **0.90461**.

Вес ансамбля и размер декабрьской надбавки **подобраны по скору на платформе** (организаторы это разрешили), все попытки — в разделе «Подбор параметров по скору».

`outputs/submission_final.csv` побайтно совпадает с отправленным файлом со скором 0.90461 (sha256 `05d73ac9bff3364c…`). `submission_math_v1.csv` совпадает с отправленным файлом 0.90339. Прошлые финалы собираются флагами: `--blend-weight 0.5 --dec-mean 0.0285` → 0.90447 (sha256 `0b0881dac32cf37e…`), плюс `--final ramp` → 0.90321. Получить финальный файл можно двумя способами:

- `python run_all.py` — обучение с нуля;
- `python run_all.py --use-artifacts` — из сохранённых моделей.

## Запуск (Python)

```
pip install -r requirements.txt
set TRAM_DATA=C:\...\dataset        # папка с labels/labels_day_train.csv, labels_day_test.csv и test_submission.csv
python run_all.py                   # обучение ML + артефакты + все шаги (несколько минут)
python run_all.py --use-artifacts   # без обучения: инференс сохранёнными моделями (LightGBM)
python run_all.py --use-artifacts --engine onnx   # инференс через ONNX Runtime (Python)
python run_all.py --use-artifacts --engine jvm    # инференс в JVM (сначала собрать jvm/, см. ниже)
python run_all.py --blend-weight 0.5 --dec-mean 0.0285                # прошлый финал 0.90447
python run_all.py --final ramp --blend-weight 0.5 --dec-mean 0.0285   # ещё раньше: без ансамбля с математикой v1 (0.90321)
python run_all.py --no-nov1-tail    # без хвоста 1 ноября
python src/export_onnx.py           # пересобрать artifacts/onnx из artifacts/*.txt и сверить
```

Если `TRAM_DATA` не задан, данные ищутся в папке `../..` (то есть при размещении в `dataset/predictions/tram_final`). Файл `test.csv` необязателен: без него хвост 1.11 берётся из `assets/nov1_tail.json`.

## ML-контур

### Потоковый режим

```python
m = TramStreamModel(mode='anchor').fit('2025-10-31')     # или .load_artifacts('artifacts', '2025-10-31', engine='onnx'|'jvm')
for day in pd.date_range('2025-11-01', '2025-12-31'):
    pred = m.predict_day(day)          # 10 маршрутов × 24 часа
    # пришли факты за день -> m.observe(day, actual): модель сразу переякоривается на них
m.write_submission('outputs/submission_ml_stream_anchor.csv')
```

Есть два режима лагов:

- `anchor` — лаги строятся по последним полученным фактам, ошибка не накапливается;
- `recursive` — лаги строятся по фактам и собственным прогнозам.

### Модели

- **Объём по часам** — ансамбль LightGBM: 3 конфигурации признаков × 5 seed, objective L1.
  - Цель — отклонение от лага того же типа дня (будни / суббота / воскресенье-праздник), нормированное на уровень маршрута.
  - Вес наблюдения падает вдвое каждые 30 дней.
  - Признаки: маршрут, час, день недели, тип дня, праздник, предпраздничный день, длина и позиция блока выходных, школьные каникулы, флаг ограничений движения 7/50, лаги из потока (`manifest.json`).
- **Профиль часов** — LightGBM (доля часа в сутках). Смешивается 50/50 с профилем модели объёма.
- **Постобработка.** `pred = scale × (mean_cfg(mean_seed(model(x))) + B)`. В рабочую субботу 01.11 берётся среднее двух кодировок типа дня. Часы 1–4 = 0.

### Артефакты и ONNX

- `artifacts/*.txt` — бустеры в родном формате LightGBM.
- `artifacts/onnx/*.onnx` — те же модели, конвертированные `onnxmltools` (ONNX IR 4, opset 8 + ai.onnx.ml 1).
- Расхождение ONNX и LightGBM: не больше **6,1·10⁻⁷** (`validation.json`).

### Инференс в JVM (ONNX Runtime for Java)

```
cd jvm
mvn -q package                                                              # единственная зависимость: com.microsoft.onnxruntime:onnxruntime
java -jar target/tram-onnx-inference-1.0-jar-with-dependencies.jar validate ../artifacts   # сверка с LightGBM
cd .. && python run_all.py --use-artifacts --engine jvm                     # полный прогноз, деревья считает JVM
```

- `validate` прогоняет контрольные строки признаков через все 16 моделей и сравнивает их с ответами LightGBM из Python.
- `serve` — движок для `stream.py --engine jvm`:
  - Python строит признаки каждого дня и отправляет матрицу в процесс Java (stdin, float32);
  - Java считает модели и возвращает прогнозы в stdout;
  - постобработка остаётся в Python.
  - За прогноз ноября–декабря получается 991 вызов моделей на 214 056 строк признаков.
- Библиотечный API — класс `TramOnnxModel`: `predictVolume(cfg, x)` (среднее по seed) и `predictShape(x)`. Порядок признаков берётся из `manifest.json`.
- Другая команда запуска Java задаётся переменной `TRAM_JVM_CMD`, например `java -cp ... ru.tram.TramOnnxInference`.

Что проверено:

- `validate`: max |ONNX(JVM) − LightGBM(Python)| = **1,2·10⁻⁷** → OK.
- Полный прогноз `--engine jvm` **побайтно совпадает** с `--engine onnx` (ONNX Runtime в Python).
- Отличие от LightGBM:
  - ML-часть — 3 ячейки из 14 640 на ±1 пассажира (округление float32);
  - итоговый файл — 2 ячейки на ±1 (`outputs/submission_final_jvm_engine.csv`).
  - Влияние на метрику ≤ 2·10⁻⁷, то есть те же 0.90461.

О среде проверки: в ней Maven Central был недоступен, поэтому `mvn package` там не запускался. Java-код проверен так:

- ONNX Runtime for Java 1.25.0 собран из исходников (github.com/microsoft/onnxruntime, тег v1.25.0);
- с ним скомпилирован `TramOnnxInference.java` (`javac --release 17`);
- запущены `validate` и полный конвейер.

В `pom.xml` указана версия 1.19.2. Используемый API в ней тот же, а модели с IR 4 / opset 8 читаются любой версией.

## Подбор параметров по скору (разрешено организаторами)

Каждая отправка меняла один параметр модели относительно лучшего на тот момент варианта. Все варианты собираются `run_all.py` с флагами.

| Шаг | Параметры (флаги `run_all.py`) | Скор | Решение |
|---|---|---|---|
| база | `--blend-weight 0.5 --dec-mean 0.0285` | 0.90447 | — |
| 1 | декабрьская надбавка `--dec-mean 0.057` | 0.90453 | принято |
| 2 | + маршрут 5 ×0,75 `--r5-scale 0.75` | 0.90415 | отклонено (множитель 1,0 оставлен) |
| 3 | + доля ML-гибрида `--blend-weight 0.4` | **0.90461** | принято → финал |

Для веса ансамбля есть три точки: 0 (только математика v1) — 0.90339, 0,4 — 0.90461, 0,5 — 0.90453. Лучший вес по ним ≈ 0,40.

Параметр `--restore-7-50` (первые выходные с обычным движением 7 и 50) оставлен на 15.11.

## Бэктест (история 2025)

Метод гибрида, обучение до 30.09, прогноз октября: **score 0.9118**. Сезонная надбавка и хвост 1.11 в октябре не действуют. WAPE по маршрутам (`reports/wape_by_route_final_method_october.csv`):

| Маршрут | 1 | 7 | 11 | 12 | 17 | 25 | 26 | 28 | 50 | Все |
|---|---|---|---|---|---|---|---|---|---|---|
| WAPE | 0.083 | 0.094 | 0.091 | 0.073 | 0.061 | 0.161 | 0.075 | 0.140 | 0.131 | **0.088** |

Ансамбль с математикой на истории не проверяется как выигрыш: на октябре ML отдельно даёт 0.9116, ядро математической модели — 0.906, их смесь 50/50 — 0.9105. Прибавка финального ансамбля видна только на ноябре–декабре (платформа), поэтому вес ансамбля (0,4) честно отнесён к подбору по скору на платформе.

Горизонт 2 месяца (обучение до 31.08, прогноз сентября–октября): score 0.821. Период тяжёлый — ремонт и ограничения 7/50 с 06.09 (`reports/wape_by_route_final_method_sep_oct.csv`).
