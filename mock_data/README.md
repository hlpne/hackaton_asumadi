# Демонстрационные данные

`service_hours.json` остаётся запасным условным окном 5:00–1:00 МСК для старых
запросов `PT1M`/`PT1H` и запуска без PostgreSQL. В режиме `resolution=schedule`
backend читает импортированные JSON 60661/60662/60664/60666 из таблиц
`transit_*`; точки ряда соответствуют времени прибытия по календарю.

`tram_schedule.jsonl.gz` — закреплённый компактный снимок этих наборов только для
36 трамвайных маршрутов. Он хранится в Git и позволяет наполнить таблицы расписания
после обычного клонирования без исходного файла на 1,4 ГБ.

`catalog.json` содержит 36 трамвайных маршрутов и 2132 остановки (включая оба направления), их названия, координаты и порядок обхода. География получена из сохранённого снимка OpenStreetMap; прогноз загрузки остаётся синтетическим.

Один источник наполняет два режима: `MemoryCatalog` читает этот JSON, а PostgreSQL
получает SQL, созданный тем же детерминированным генератором:

```bash
python db/seed/generate_seed.py
```

`002_demo.sql` содержит 52032 почасовых прогнозов на 26 сентября 2026 года: по 24
точки для каждого маршрута и остановки. У рядов различаются
базовые уровни, а утром и вечером возникают пики. Повторная генерация создаёт
байт-в-байт те же `catalog.json` и SQL.

Mock Predictor вычисляет воспроизводимый условный индекс. Идентификаторы определяют базовый уровень через SHA-256; время добавляет синтетические утренний и вечерний пики. Для дневных и месячных точек используется среднее часового индекса внутри интервала. Это проверяет контракт и интерфейс, а не имитирует точность реальной модели.

`lower_bound` и `upper_bound` у mock — иллюстрация для интерфейса. Статистический уровень покрытия не заявлен: `interval_level: null`. Второй провайдер `constant` возвращает значение 42 и обе границы `null`.
